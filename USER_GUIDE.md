# User guide

The current interface follows CASE FILE NOIR. The original detective emblem includes a deerstalker and curved pipe. See docs/CASE_FILE_NOIR.md for the editable design and docs/NOIR_PORTABLE_RELEASE.md for transfer instructions.

Start `START_SHERLOCKED.bat` from the project folder, then open http://127.0.0.1:8501. You will first see the branded landing page and local sign-in. Once signed in, the grouped sidebar contains six core workspaces and the separate Ashford Manor demo corpus. Quick jump is available in the top bar, and appearance is selectable on entry and workspace screens. On a narrow window, use the upper-left double chevron to open navigation. All input reports must be fictional.

## Welcome and local access

The opening page presents the original detective identity and a static capability overview. **Enter the research lab** or **Investigator access** opens sign-in; **Overview** returns from sign-in to the landing page. The landing page has no working report preview, report selectors or source handoff. After sign-in, use Report Explorer or AI Analysis Workspace to browse reports, inspect source previews, enter text and run retrieval.

For the unchanged local demonstration account, use username **demo** and password **sherlocked-demo**. They are also listed under Local demonstration access. An existing changed password is retained. Incorrect details show a generic error; five failures within one minute temporarily lock that username for one minute. Wait for the lock rather than repeatedly retrying.

Use **Dark mode / Light mode** on welcome, login or the lab. The selected appearance remains across navigation and is recorded as `theme=light` or `theme=dark` in the URL for reload continuity. Tables and measurement heatmaps intentionally remain paper-like, while the relationship graph stays ink. Both preserve the original Noir identity.

**Sign out** returns to welcome and clears the current access/analysis session while retaining appearance. It does not delete reports or saved results. There is no remember-me token, so reopening or reloading may require sign-in again. Local credentials are stored as salted password hashes in the separate configured dataset directory's `local_access.sqlite3`, not the report database. This public fictional-demo gate is not enterprise access control. See [entry and appearance notes](docs/ENTRY_AND_THEMES.md).

## Inside the laboratory

1. **Intelligence Dashboard:** actual dataset/language/family counts, cached model status and latest saved measured experiment. Experiment metrics belong to the displayed dataset/split/K, not the whole application. Source-only and annotation-assisted conditions differ.
2. **Report Explorer:** filter original reports by ID/text/metadata, language and incident type. Select a report to inspect full text, mentions and provenance. Use it in analysis, or export filtered JSONL. The submission tab accepts text or UTF-8 files and optional annotated metadata after fictional-data confirmation. Duplicate/conflicting records are not overwritten.
3. **AI Analysis Workspace:** select an existing report or paste new text; the Source preview or upload expander contains the optional UTF-8 uploader. Then choose TF-IDF, BM25, semantic, entity, structured, weighted hybrid, RRF or heuristic reranking. Existing-query self matches are excluded. Manually confirm optional metadata if known. Run discovery and inspect ranked candidates and select a candidate to open Signal profile, Source passages, Entities & context and Computational record tabs. A semantic passage pair is illustrative evidence, not a causal explanation of the encoder. JSON exports contain all evidence; CSV exports contain rankings. Results retain their executed method until you rerun; changing an input alone does not change saved results.
4. **Relationship Explorer:** choose a central report and method, then build a graph. Dashed rose edges are computed report suggestions; solid grey edges document literal source mentions; dotted brass edges compare mentions; oxblood marks actual recorded differences. Ivory identifies the current source. The review gate remains UNREVIEWED and does not store analyst decisions. Use layer/type filters and graph search. Pan/zoom the canvas and select nodes or edge midpoints, or use the inspector selection, to read actual source evidence. Export graph evidence as JSON. No verified relationship is created.
5. **Research Evaluation Lab:** choose original or challenge dataset, methods, development split and cutoff. Source-only extraction is enabled by default to exclude supplied annotation shortcuts. Add ablations if desired. Run evaluation, inspect actual tables/charts, slices, bootstrap intervals, missed siblings and unrelated results, and export JSON/CSV. Test requires acknowledging frozen configuration; do not use test results to tune weights.
6. **System Settings:** configure CPU/auto/CUDA, BM25 k1/b, RRF constant and nonnegative fusion weights. Save changes before new searches. Prepare the pinned semantic model explicitly; existing local files are reused. Run health checks, import validated fictional JSONL atomically, or export the SQLite workspace. Canonical fixture files remain separate from submitted reports.

7. **Ashford Manor:** a separate newly authored six-source fictional archive, original schematic plan and source-dated timeline. Select an archive source and run Analyze archive links for real retrieval over those six reports only. This illustrative case is excluded from the database and research benchmarks.

If semantic setup fails, its error is displayed. TF-IDF/BM25 remain available as explicit alternatives. Latin-only Banglish script detection is labelled English; this is a documented heuristic, not robust language identification. Missing metadata is unknown. Fuzzy entity matches are tentative and never merge identities. Similarity scores are not probabilities or guilt scores. Current retrieval has no validated abstention threshold: unrelated reports may still receive positive scores.

The original 90-report benchmark and separate 39-report challenge are synthetic fixtures, not independently annotated research benchmarks. Results cannot be generalized to real investigations. The local demonstration access gate is not enterprise authentication; do not expose this research demonstration publicly or enter real sensitive reports.
